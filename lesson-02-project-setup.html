Lesson 2: Project Setup (.NET 8)

This lesson creates the MVC project, explains the default structure, and shows how the .NET 8 hosting model wires the application together with one Program.cs file.

Introduction

A clean starting point makes later lessons easier. We will use the official MVC template, keep the project small, and route the default page to our Todo controller.

Key Concepts

  • Create the project with the .NET 8 SDK.
  • Understand standard MVC folders: Controllers, Models, Views, and wwwroot.
  • Use Program.cs for service registration and middleware.
  • Run the app with dotnet run and verify routing.

This structure keeps MVC concerns clear while giving you dedicated places for data access, business logic, extensions, middleware, and static assets. Small tutorial apps can start with fewer folders, but this layout scales better as the application grows.

Why Teams Prefer This Structure

  • Controllers stay focused on HTTP requests and responses.
  • Models hold domain data, enums, and validation rules.
  • Interfaces keeps contracts separate from implementations, which helps with testing and dependency injection.
  • Data contains repositories, DbContext, and persistence concerns.
  • Services handle business rules that should not live in controllers.
  • Extensions keeps reusable helper methods easy to find.
  • Middleware contains cross-cutting request pipeline behavior.
  • Filters is a good place for action filters and reusable MVC request rules.
  • Handlers can hold focused processing logic when features grow beyond simple service methods.
  • Helpers works well for shared utility logic that does not belong to a service or model.
  • Views remains organized by feature, which is easier to navigate in larger MVC projects.

Explain Program.cs

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllersWithViews();

var app = builder.Build();

if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseRouting();
app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Todo}/{action=Index}/{id?}");

app.Run();

builder.Services is where we register framework and application services. app defines middleware and routes. This single file replaces the older split between Program.cs and Startup.cs.

Nullable Context in Modern .NET Projects

<Project Sdk="Microsoft.NET.Sdk.Web">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
</Project>

.NET 8 projects commonly enable nullable reference types in the project file. This helps the compiler warn you when code may pass or return null in unsafe ways. It is one of the most important quality-of-life features in modern C#.

Null Coalescing and Null-Forgiving Operator

string? connectionString = builder.Configuration.GetConnectionString("TodoDb");

string safeConnectionString = connectionString ?? "FallbackConnection";

string requiredConnectionString = builder.Configuration
    .GetConnectionString("TodoDb")
    ?? throw new InvalidOperationException("Missing TodoDb connection string.");

string trustedValue = connectionString!;

The null-coalescing operator ?? gives you a fallback when a value is null. The null-forgiving operator ! tells the compiler to stop warning about possible null, but it should only be used when you are truly certain the value exists. In most cases, a fallback or explicit exception is safer than force unwrapping.
