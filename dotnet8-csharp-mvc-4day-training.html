3. OOP, Collections, LINQ, Enums, and Extension Methods

Object-Oriented Programming (OOP) syntax breakdown:
In public class TodoItem, the keyword public means the type is accessible from other assemblies. The keyword class defines a reference type. Properties like public int Id { get; set; } use accessors: get reads the value and set writes the value. Initializers such as = string.Empty prevent null issues and satisfy nullable reference rules.

Collections syntax breakdown:
List<TodoItem> is a generic collection; <TodoItem> specifies the element type. new() is target-typed object creation and uses the left side type (List<TodoItem>) to infer constructor type. Collection initializers with braces add items immediately.

LINQ syntax breakdown:
Each call in the chain returns an enumerable sequence. Where(...) filters, OrderByDescending(...) sorts, and Select(...) projects into a new shape. Lambda syntax t => ... means: input parameter t maps to expression result. The final query is deferred until iteration in foreach.

Enum syntax breakdown:
public enum TodoPriority { Low = 1, Medium = 2, High = 3 } creates named constants backed by int. Explicit numeric assignments are helpful for persistence/API contracts.

Extension method syntax breakdown:
A static class (TodoExtensions) contains a static method where the first parameter is prefixed by this. In ToStatusLabel(this TodoItem todo), this TodoItem extends TodoItem as if it had an instance method. Expression-bodied syntax => returns a value in one line. 

using System;
using System.Collections.Generic;
using System.Linq;

public enum TodoPriority
{
    Low = 1,
    Medium = 2,
    High = 3
}

public class TodoItem
{
    public int Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public bool IsCompleted { get; set; }
    public TodoPriority Priority { get; set; }
}

public static class TodoExtensions
{
    public static string ToStatusLabel(this TodoItem todo)
        => todo.IsCompleted ? "Completed" : "Pending";
}

var todos = new List<TodoItem>
{
    new() { Id = 1, Title = "Setup solution", IsCompleted = true, Priority = TodoPriority.High },
    new() { Id = 2, Title = "Create models", IsCompleted = false, Priority = TodoPriority.Medium },
    new() { Id = 3, Title = "Build views", IsCompleted = false, Priority = TodoPriority.Low }
};

var pendingHighPriority = todos
    .Where(t => !t.IsCompleted && t.Priority == TodoPriority.Medium || t.Priority == TodoPriority.High)
    .OrderByDescending(t => t.Priority)
    .Select(t => new { t.Title, Status = t.ToStatusLabel(), t.Priority });

foreach (var item in pendingHighPriority)
{
    Console.WriteLine($"{item.Title} | {item.Priority} | {item.Status}");
}
Best Practice: Prefer expressive names and immutable DTOs where possible; avoid large god classes by separating domain concerns.

1. Nullable Reference Types, Pattern Matching, and Switch Expressions

Nullable reference type syntax:
#nullable enable activates nullable analysis in this file scope. In string? Department, the ? indicates the property may be null. If you declare string Name without ?, the compiler expects non-null assignment.

Record syntax:
public record UserProfile(string Name, string? Department); defines an immutable data-centric type with generated constructor, value equality, and deconstruction.

Switch expression syntax:
In profile.Department switch { ... }, each arm maps a pattern to a result. null or "" => "No Department" combines patterns with or. The underscore arm _ => "General" is the fallback/default arm.

Pattern matching syntax:
int n when n > 0 is a type pattern plus guard clause. string { Length: > 0 } s is a property pattern that matches non-empty strings and captures the value in s. Pattern matching helps replace deep if/else blocks with explicit, testable rules. 

#nullable enable
using System;

public record UserProfile(string Name, string? Department);

public static class UserFormatter
{
    public static string GetDepartmentLabel(UserProfile profile)
        => profile.Department switch
        {
            null or "" => "No Department",
            "IT" => "Technology",
            "HR" => "Human Resources",
            _ => "General"
        };

    public static string Describe(object value) => value switch
    {
        int n when n > 0 => $"Positive number: {n}",
        int _ => "Non-positive number",
        string { Length: > 0 } s => $"Text: {s}",
        null => "Null value",
        _ => "Unknown type"
    };
}

2. Using Declarations, Index/Range, Async/Await, and Tasks

Using declaration syntax:
using var reader = new StreamReader(filePath); declares a disposable resource that is automatically disposed at the end of the current scope, without needing an explicit using (...) { } block.

Index and range syntax:
words[..Math.Min(10, words.Length)] means start at index 0 and slice up to (but not including) the computed end. This is cleaner than manual loops for subarray extraction.

Async method syntax:
Methods marked async can use await. The return type is typically Task or Task<T>. await reader.ReadToEndAsync(...) asynchronously waits for I/O completion without blocking thread execution.

Task orchestration syntax:
Task.WhenAll(taskA, taskB) composes multiple tasks and asynchronously resumes when all complete. This is useful for parallel I/O operations in service and controller layers. 

using System;
using System.IO;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;

public class ReportService
{
    public async Task<string> ReadPreviewAsync(string filePath, CancellationToken cancellationToken = default)
    {
        using var reader = new StreamReader(filePath); // using declaration
        string content = await reader.ReadToEndAsync(cancellationToken);

        string[] words = content.Split(' ', StringSplitOptions.RemoveEmptyEntries);
        string preview = string.Join(' ', words[..Math.Min(10, words.Length)]); // range operator

        return preview;
    }

    public async Task<int> SimulateWorkAsync()
    {
        Task<int> taskA = Task.Run(async () =>
        {
            await Task.Delay(100);
            return 10;
        });

        Task<int> taskB = Task.Run(async () =>
        {
            await Task.Delay(150);
            return 20;
        });

        int[] results = await Task.WhenAll(taskA, taskB);
        return results.Sum();
    }
}
Best Practice: In ASP.NET Core, avoid .Result / .Wait(); use async/await end-to-end to prevent thread starvation and deadlocks.

1. MVC Architecture, Project Structure, Controllers, and Actions

MVC separation syntax:
Models represent application state and validation rules. Views are Razor templates that render HTML. Controllers are classes inheriting from Controller and expose action methods that return IActionResult.

Minimal hosting syntax in .NET 8:
var builder = WebApplication.CreateBuilder(args); creates the host and configuration pipeline. builder.Services.AddControllersWithViews(); registers MVC services in DI. var app = builder.Build(); builds the configured app. Middleware calls such as app.UseRouting() and endpoint mapping via app.MapControllerRoute(...) define how requests flow to controllers and actions. 

// Program.cs (.NET 8)
using Microsoft.EntityFrameworkCore;
using TodoTrainingApp.Data;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllersWithViews();
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));

var app = builder.Build();

if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseRouting();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

app.Run();

2. Routing, Model Binding, Razor Views, Layouts, Partial Views, and Tag Helpers

Controller and action syntax:
Attributes like [HttpGet] and [HttpPost] constrain which HTTP verbs can invoke an action. [ValidateAntiForgeryToken] enforces CSRF protection for form posts. return View(model); passes a model object to Razor. RedirectToAction(nameof(Index)) performs a PRG (Post/Redirect/Get) flow.

Model binding syntax:
In public IActionResult Create(Todo model), MVC binds form fields to the Todo object by matching names. ModelState.IsValid checks data-annotation validation before persistence.

Razor and Tag Helper syntax:
@model TodoTrainingApp.Models.Todo defines the view model type. asp-for="Title" binds an HTML element to the Title property and emits proper name/id attributes. asp-validation-for="Title" renders validation messages. asp-action="Create" generates form post target URLs from routing metadata. 

using Microsoft.AspNetCore.Mvc;
using TodoTrainingApp.Models;

namespace TodoTrainingApp.Controllers;

public class TodoController : Controller
{
    private static readonly List<Todo> Todos = new();

    public IActionResult Index() => View(Todos);

    [HttpGet]
    public IActionResult Create() => View();

    [HttpPost]
    [ValidateAntiForgeryToken]
    public IActionResult Create(Todo model)
    {
        if (!ModelState.IsValid)
        {
            return View(model);
        }

        model.Id = Todos.Count + 1;
        Todos.Add(model);

        return RedirectToAction(nameof(Index));
    }
}
@model TodoTrainingApp.Models.Todo

<form asp-action="Create" method="post">
    <div class="mb-3">
        <label asp-for="Title" class="form-label"></label>
        <input asp-for="Title" class="form-control" />
        <span asp-validation-for="Title" class="text-danger"></span>
    </div>

    <div class="form-check">

1. View Components, Areas, DI, Service Architecture, Repository Basics

View Component syntax:
A class inheriting ViewComponent encapsulates reusable UI + logic. InvokeAsync() returns IViewComponentResult, often a partial-like view with a focused model. This keeps layout-level widgets (for example "Pending Todos") out of controllers.

Dependency Injection syntax:
Constructor injection (PendingTodosViewComponent(ITodoService todoService)) requests dependencies from the container. Service registration lines such as AddScoped<ITodoService, TodoService>() map abstractions to implementations per request scope.

Areas and service architecture:
Areas organize large applications into feature segments (e.g., Admin, Support). Services hold business rules and orchestration, while repositories focus on persistence queries/commands. This split improves testability and reduces controller complexity. 

using Microsoft.AspNetCore.Mvc;
using TodoTrainingApp.Services;

namespace TodoTrainingApp.ViewComponents;

public class PendingTodosViewComponent : ViewComponent
{

    {
        _todoService = todoService;
    }

    public async Task<IViewComponentResult> InvokeAsync()
    {
        var pending = await _todoService.GetPendingAsync();

2. Final Project: Todo Management System (Users ↔ Todos)

Domain modeling syntax:
The User entity includes scalar columns and a navigation collection ICollection<Todo> Todos. The Todo entity has foreign key UserId and reference navigation User?. This pair defines one-to-many cardinality in code-first EF Core.

Validation syntax:
Data annotations like [Required], [StringLength(...)], and [EmailAddress] provide server-side validation metadata used by MVC model validation.

DbContext fluent API syntax:
modelBuilder.Entity<User>().HasIndex(u => u.Email).IsUnique() creates a unique index. Relationship mapping uses HasOne(...).WithMany(...).HasForeignKey(...). OnDelete(DeleteBehavior.Cascade) configures dependent-row deletion behavior.

Controller + DI + routing syntax:
In the final controller, constructor-injected services are used in async actions. public async Task<IActionResult> Index() returns a view after awaiting data access. Helpers like SelectListItem transform user entities into dropdown options for Razor forms.

using System.ComponentModel.DataAnnotations;

namespace TodoTrainingApp.Models;

public class User
{
    public int Id { get; set; }

    [Required, StringLength(100)]
    public string Name { get; set; } = string.Empty;

    [Required, EmailAddress, StringLength(150)]
    public string Email { get; set; } = string.Empty;

    public ICollection<Todo> Todos { get; set; } = new List<Todo>();
}

public class Todo
{
    public int Id { get; set; }

    [Required, StringLength(200)]
    public string Title { get; set; } = string.Empty;

    public bool IsCompleted { get; set; }

    public int UserId { get; set; }
    public User? User { get; set; }
}
using Microsoft.EntityFrameworkCore;
using TodoTrainingApp.Models;

namespace TodoTrainingApp.Data;

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }

    public DbSet<User> Users => Set<User>();
    public DbSet<Todo> Todos => Set<Todo>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<User>()
            .HasIndex(u => u.Email)
            .IsUnique();

        modelBuilder.Entity<Todo>()
            .HasOne(t => t.User)
            .WithMany(u => u.Todos)
            .HasForeignKey(t => t.UserId)
            .OnDelete(DeleteBehavior.Cascade);
    }
}
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Rendering;
using TodoTrainingApp.Models;
using TodoTrainingApp.Services;

namespace TodoTrainingApp.Controllers;

public class TodoController : Controller
{
    private readonly ITodoService _todoService;
    private readonly IUserService _userService;

    public TodoController(ITodoService todoService, IUserService userService)
    {
        _todoService = todoService;
        _userService = userService;
    }

    public async Task<IActionResult> Index()
        => View(await _todoService.GetAllAsync());

    [HttpGet]
    public async Task<IActionResult> Create()
    {
        await LoadUsersAsync();
        return View(new Todo());
    }

    [HttpPost]
    [ValidateAntiForgeryToken]
    public async Task<IActionResult> Create(Todo model)
    {
        if (!ModelState.IsValid)
        {
            await LoadUsersAsync();
            return View(model);
        }

        await _todoService.CreateAsync(model);
        return RedirectToAction(nameof(Index));
    }

    private async Task LoadUsersAsync()
    {
        var users = await _userService.GetAllAsync();
        ViewBag.Users = users.Select(u => new SelectListItem
        {
            Value = u.Id.ToString(),
            Text = $"{u.Name} ({u.Email})"
        }).ToList();
    }
}
