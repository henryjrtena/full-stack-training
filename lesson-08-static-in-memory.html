Prototype Storage

Lesson 8: Static In-Memory Implementation (No DI)

Before introducing dependency injection and databases, we can learn the application flow with a simple static store.

Introduction

An in-memory implementation is perfect for demos and early lessons because it removes infrastructure complexity. It is not suitable for production, but it makes the MVC flow easy to understand.

Key Concepts

  • A static store keeps data only while the process is running.
  • List<TodoItem> is enough for learning CRUD.
  • We can still write async methods even if the work is local.
  • This version intentionally avoids DI to show the contrast in the next lesson.

Step-by-Step

Create the Static Store

using TodoMvcApp.Models;

namespace TodoMvcApp.Data;

public static class TodoStore
{
    private static readonly List<TodoItem> Items =
    [
        new() { Id = 1, Title = "Learn MVC", DueDate = DateOnly.FromDateTime(DateTime.Today.AddDays(1)) },
        new() { Id = 2, Title = "Add AJAX form", IsCompleted = true }
    ];

    private static int _nextId = 3;

    public static Task<IReadOnlyList<TodoItem>> GetAllAsync(CancellationToken cancellationToken)
    {
        cancellationToken.ThrowIfCancellationRequested();
        return Task.FromResult<IReadOnlyList<TodoItem>>(Items.OrderBy(x => x.Id).ToList());
    }

    public static Task AddAsync(TodoItem item, CancellationToken cancellationToken)
    {
        cancellationToken.ThrowIfCancellationRequested();
        item.Id = _nextId++;
        Items.Add(item);
        return Task.CompletedTask;
    }
}

Use the Store in the Controller

using Microsoft.AspNetCore.Mvc;
using TodoMvcApp.Data;
using TodoMvcApp.Models;

namespace TodoMvcApp.Controllers;

public sealed class TodoController : Controller
{
    public async Task<IActionResult> Index(CancellationToken cancellationToken)
    {
        var items = await TodoStore.GetAllAsync(cancellationToken);
        return View(items);
    }

    [HttpPost]
    [ValidateAntiForgeryToken]
    public async Task<IActionResult> Create(TodoItem item, CancellationToken cancellationToken)
    {
        if (!ModelState.IsValid)
        {
            return View(item);
        }

        await TodoStore.AddAsync(item, cancellationToken);
        return RedirectToAction(nameof(Index));
    }
}

Limitations

This design loses data on restart, is shared across all users, and is harder to test cleanly than an injected service. Those limitations are exactly why dependency injection is the next step.

Summary

The static store helps us validate the end-to-end behavior quickly, but it mixes storage directly into the controller experience. Next we will modernize the design with .NET 8 dependency injection.
