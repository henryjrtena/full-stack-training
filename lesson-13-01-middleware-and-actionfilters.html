Pipeline and MVC Hooks

Lesson 13.2: Middleware and Action Filters

This bridge lesson explains two important extension points in ASP.NET Core: middleware in the HTTP pipeline and action filters in the MVC pipeline. Both help you apply cross-cutting behavior, but they operate at different levels.

Introduction

As applications grow, some logic needs to happen for many requests, not just one controller action. Logging, exception handling, timing, authentication checks, and request enrichment are common examples. ASP.NET Core gives you middleware and action filters to handle those concerns cleanly.

Key Concepts

  • Middleware runs in the ASP.NET Core HTTP request pipeline.
  • Action filters run around MVC controller actions.
  • Middleware is broader and can affect all incoming requests.
  • Action filters are more MVC-specific and work well for controller-focused behavior.
  • Choosing the right one depends on where the concern belongs.

Step-by-Step

What Middleware Does

Request
  -> Middleware 1
  -> Middleware 2
  -> Middleware 3
  -> MVC Routing
  -> Controller Action
  -> Response

Middleware sits in the request pipeline before MVC gets control. It can inspect the request, short-circuit the pipeline, call the next middleware, and inspect or modify the response on the way back out.

Create Custom Middleware

public sealed class RequestTimingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestTimingMiddleware> _logger;

    public RequestTimingMiddleware(
        RequestDelegate next,
        ILogger<RequestTimingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        var startedAt = DateTime.UtcNow;

        await _next(context);

        var duration = DateTime.UtcNow - startedAt;
        _logger.LogInformation(
            "Request {Path} completed in {DurationMs} ms",
            context.Request.Path,
            duration.TotalMilliseconds);
    }
}

Register Middleware in Program.cs

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllersWithViews();

var app = builder.Build();

app.UseMiddleware<RequestTimingMiddleware>();
app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseRouting();
app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Todo}/{action=Index}/{id?}");

app.Run();

This is one of the clearest signs that middleware belongs to the application pipeline, not just to MVC.

What an Action Filter Does

Request
  -> Middleware
  -> MVC
  -> Action Filter
  -> Controller Action
  -> Action Filter
  -> Response

Action filters run closer to the controller action itself. They are ideal when the behavior only makes sense for MVC actions, such as validating route data, logging action execution, or applying action-specific rules.

Create an Action Filter

using Microsoft.AspNetCore.Mvc.Filters;

public sealed class AuditActionFilter : IActionFilter
{
    private readonly ILogger<AuditActionFilter> _logger;

    public AuditActionFilter(ILogger<AuditActionFilter> logger)
    {
        _logger = logger;
    }

    public void OnActionExecuting(ActionExecutingContext context)
    {
        _logger.LogInformation(
            "Executing action {ActionName}",
            context.ActionDescriptor.DisplayName);
    }

    public void OnActionExecuted(ActionExecutedContext context)
    {
        _logger.LogInformation(
            "Executed action {ActionName}",
            context.ActionDescriptor.DisplayName);
    }
}

Register and Use the Filter

builder.Services.AddScoped<AuditActionFilter>();

builder.Services.AddControllersWithViews(options =>
{
    options.Filters.AddService<AuditActionFilter>();
});

You can also apply filters to a specific controller or action instead of globally.

Per-Action Filter Example

[ServiceFilter(typeof(AuditActionFilter))]
public sealed class TodoController : Controller
{
    public IActionResult Index()
    {
        return View();
    }
}

Middleware vs Action Filter

// Use middleware for:
// - global exception handling
// - request logging
// - authentication pipeline work
// - response headers

// Use action filters for:
// - action-specific logging
// - MVC validation behavior
// - checking route or action arguments
// - controller-level cross-cutting rules

A good rule of thumb is this: if the concern belongs to every HTTP request, consider middleware first. If it belongs specifically to MVC action execution, consider an action filter.

Example for the Todo App

In this Todo application, middleware is a great place for global exception handling and request timing. Action filters are a good fit for auditing controller actions or checking whether a Todo item exists before allowing an edit or delete action to continue.

Summary

Middleware and action filters both help you keep controller code cleaner, but they solve different kinds of problems. Middleware works at the application pipeline level, while action filters work at the MVC action level. Knowing when to use each will make your ASP.NET Core applications easier to structure and maintain.
