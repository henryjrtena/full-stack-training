Validation

Lesson 5: Client-Side Validation

Client-side validation improves the form experience by showing errors immediately, while server-side validation still remains the final authority.

Introduction

ASP.NET Core MVC uses model metadata from data annotations to generate validation rules. jQuery Validation and jQuery Unobtrusive Validation then read those rules from the rendered HTML.

Key Concepts

  • Data annotations drive both client-side and server-side validation.
  • asp-validation-for shows field-level messages.
  • asp-validation-summary shows broader form errors.
  • Validation scripts are usually loaded from the shared layout or a partial.

Step-by-Step

Add Validation Summary

@model TodoMvcApp.Models.TodoItem

<form asp-action="Create" method="post">
    @Html.AntiForgeryToken()
    <div asp-validation-summary="ModelOnly" class="text-danger"></div>

    <label asp-for="Title"></label>
    <input asp-for="Title" class="form-control" />
    <span asp-validation-for="Title" class="text-danger"></span>

    <button type="submit">Save</button>
</form>

Render the Validation Script Partial

@section Scripts {
    <partial name="_ValidationScriptsPartial" />
}

Example Partial Content

<script src="~/lib/jquery/dist/jquery.min.js"></script>
<script src="~/lib/jquery-validation/dist/jquery.validate.min.js"></script>
<script src="~/lib/jquery-validation-unobtrusive/jquery.validate.unobtrusive.min.js"></script>

Server Validation Still Matters

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Create(TodoItem item)
{
    if (!ModelState.IsValid)
    {
        return View(item);
    }

    return RedirectToAction(nameof(Index));
}

Summary

Client-side validation makes the form feel faster and clearer, but server validation remains essential because browser rules can be bypassed. Next we will make form submission asynchronous with jQuery AJAX and a loading state.
