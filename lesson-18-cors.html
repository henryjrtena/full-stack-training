API Security

Lesson 18: CORS Configuration

Learn to configure Cross-Origin Resource Sharing (CORS) for secure cross-domain requests in your ASP.NET Core API.

Introduction

CORS (Cross-Origin Resource Sharing) is essential for modern web APIs that need to be accessed from web browsers. It controls which domains can make requests to your API and what types of requests are allowed.

Key Concepts

  • CORS enables secure cross-origin requests from web browsers.
  • Preflight requests are sent by browsers for complex HTTP methods.
  • CORS policies define allowed origins, methods, and headers.
  • Controller and action-level attributes provide fine-grained control.
  • Proper CORS configuration prevents unauthorized cross-origin access.

Step-by-Step

CORS Configuration in Program.cs

var builder = WebApplication.CreateBuilder(args);

// Add CORS services
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowSpecificOrigins", policy =>
    {
        policy.WithOrigins("https://localhost:3000", "https://myapp.com")
              .AllowAnyMethod()
              .AllowAnyHeader()
              .AllowCredentials();
    });

    options.AddPolicy("AllowAll", policy =>
    {
        policy.AllowAnyOrigin()
              .AllowAnyMethod()
              .AllowAnyHeader();
    });
});

builder.Services.AddControllers();

var app = builder.Build();

// Use CORS middleware (must be before UseRouting)
app.UseCors("AllowSpecificOrigins"); // or "AllowAll" for development

app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();
app.Run();

Configure CORS policies and apply them in the middleware pipeline. Use specific origins in production for security.

Controller with CORS Attributes

using Microsoft.AspNetCore.Cors;
using Microsoft.AspNetCore.Mvc;

namespace GroceryApi.Controllers
{
    [ApiController]
    [Route("api/[controller]")]
    [EnableCors("AllowSpecificOrigins")]
    public class GroceriesController : ControllerBase
    {
        [HttpGet]
        [DisableCors]
        public IActionResult GetGroceries()
        {
            // This endpoint disables CORS
            return Ok(new[] { "item1", "item2" });
        }

        [HttpPost]
        public IActionResult CreateGrocery([FromBody] GroceryItem item)
        {
            // This endpoint uses the controller-level CORS policy
            return CreatedAtAction(nameof(GetGrocery), new { id = 1 }, item);
        }

        [HttpGet("{id}")]
        [EnableCors("AllowAll")]
        public IActionResult GetGrocery(int id)
        {
            // This endpoint allows all origins
            return Ok(new { id, name = "Sample Item" });
        }
    }
}

Use CORS attributes at controller and action levels to fine-tune cross-origin access policies.

CORS Policy Options

// Specific origins (recommended for production)
policy.WithOrigins("https://myapp.com", "https://admin.myapp.com")

// Allow any origin (use only for development)
policy.AllowAnyOrigin()

// Allow specific HTTP methods
policy.WithMethods("GET", "POST", "PUT", "DELETE")

// Allow specific headers
policy.WithHeaders("Content-Type", "Authorization")

// Allow credentials (cookies, authorization headers)
policy.AllowCredentials()

// Set preflight cache duration
policy.SetPreflightMaxAge(TimeSpan.FromMinutes(10))

CORS policies provide granular control over cross-origin access. Always use specific origins in production environments.

Summary

CORS is crucial for securing modern web APIs that need to be accessed from web browsers. Proper CORS configuration ensures that only authorized domains can make cross-origin requests to your API.
